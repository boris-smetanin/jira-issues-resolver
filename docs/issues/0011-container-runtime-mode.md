# 0011 — Container Agent Runtime mode (HITL)

## What to build

The opt-in path from ADR-0001. When a Space toggles into container mode, the orchestrator runs the agent inside a Docker container built from a per-Space Dockerfile stored in DB. The Dockerfile is auto-generated by detecting the user's repo Dockerfile and prepending the Sandcastle agent layer. User reviews/edits in a Monaco editor before saving.

**HITL**: the generated Dockerfile needs human review per repo. Multi-stage Dockerfiles, BuildKit secrets, and language-specific quirks all force a judgment call about the merged output. An AFK agent cannot validate "did this Dockerfile actually build for this team's repo".

Build:

- `orchestrator/dockerfile.generator.ts` — pure function `generate({ repoPath }) → { content, detectedFrom: string | null, warnings: string[] }`. Algorithm:
  1. Scan candidate paths in order: `Dockerfile.dev`, `Dockerfile`, `docker/Dockerfile`, `.docker/Dockerfile`.
  2. If found, inline the content; record `detectedFrom = relative path`.
  3. If not found, start from a `FROM node:22-bookworm` skeleton; record `detectedFrom = null` + warning "No Dockerfile found in repo; using node:22 base".
  4. Detect multi-stage: parse `FROM ... AS <name>` blocks. If multi-stage, emit a warning that the Sandcastle layer attaches only to the final stage.
  5. Detect BuildKit-secret usage (`--mount=type=secret`). Emit a hard warning: "BuildKit secrets are not supported by Sandcastle's image build; edit before saving".
  6. Append the Sandcastle agent layer:
     ```
     USER root
     RUN apt-get update && apt-get install -y nodejs git curl jq \
       && rm -rf /var/lib/apt/lists/*
     RUN curl -fsSL https://claude.ai/install.sh | bash
     RUN id -u agent >/dev/null 2>&1 || \
         useradd -m -u 1000 -g 1000 -s /bin/bash agent
     USER agent
     WORKDIR /home/agent
     ENTRYPOINT ["sleep", "infinity"]
     ```
  7. Return content + diagnostics.
- `spaces` row gets `agent_runtime_mode` (already in schema from slice 0003) and `dockerfile_content` (already nullable in schema). Migration `0007_dockerfile_default.sql` if any schema tightening needed.
- New routes on api.controller:
  - `POST /api/spaces/:id/dockerfile/detect` → triggers a clone (if not yet cloned), runs `dockerfile.generator.generate()`, returns `{ content, detectedFrom, warnings }`. Does NOT save.
  - `PATCH /api/spaces/:id/dockerfile` → save `dockerfile_content` + flip `agent_runtime_mode` to `container`.
  - `PATCH /api/spaces/:id/runtime-mode` → flip `host` ↔ `container`; on flip to `host` clears `dockerfile_content`.
- `integrations/sandcastle/sandcastle.runner.ts` gets the container branch (per the locked Q17):
  ```
  if (space.agent_runtime_mode === 'container') {
    const dfPath = join(worktreePath, '.sandcastle/Dockerfile')
    mkdirSync(dirname(dfPath), { recursive: true })
    writeFileSync(dfPath, space.dockerfile_content)
    appendToGitInfoExclude(spaceClonePath, '.sandcastle/')

    return sandcastle.run({
      cwd: worktreePath,
      sandbox: bindMountProvider({
        dockerfile: dfPath,
        branchStrategy: 'head'
      }),
      agent, prompt, onAgentStreamEvent: onEvent
    })
  }
  ```
- Web: Create Space form gets a toggle "Isolate agent in container (advanced)". Off by default. Flipping on triggers a deferred-loading state with progress: "Cloning repo... Detecting Dockerfile... Generating merged Dockerfile..." Then renders a Monaco editor with the generated content and the warnings list above it. User edits → clicks Save → the editor content is sent to the API. If the user submits the form with the toggle on, the dockerfile content is required (validated).
- Web: Space settings page gets the same toggle + the editor + a "Re-detect from repo" button that re-runs the detection (overwrites the editor's current content; confirm dialog warns about losing local edits).

## Acceptance criteria

- [ ] Toggling on at Create Space: clone fires (synchronously, with progress feedback in the UI), detection runs, editor opens with merged content + any warnings, user can save.
- [ ] A Space in container mode runs its next attempt inside a Docker container (verify via `docker ps` during AGENT_RUNNING).
- [ ] A Space in host mode (default) is unaffected by this slice.
- [ ] Toggling a Space from container → host clears `dockerfile_content` (and the UI editor) but leaves attempt history intact.
- [ ] The user's repo is not modified (no commit, no working-copy file changes outside the worktree).
- [ ] `.sandcastle/` is in `.git/info/exclude` for the persistent clone so the agent's `git status` does not see it.
- [ ] HITL handoff document for a teammate adopting container mode: a one-pager (in `docs/`) describing the merged-Dockerfile review checklist (multi-stage caveat, BuildKit, what a healthy merged Dockerfile looks like).
